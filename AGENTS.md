# XR Testbed — правила проекта

Статический сайт: пять XR-опытов (Three.js + xrblocks с CDN), общий shell в `common/`.
Никакой сборки: правки проверяются открытием страницы в браузере.

## Общие правила

- Весь UI опыта строится через `common/shell.js`: `createHud` (вне сессии),
  `spatialControls` (в сессии), `baseOptions`, `anchorRoot`. Не дублировать
  эти механизмы в опытах.
- У панелей из `spatialControls` два представления: world-карта `card`
  (шлем/десктоп) и экранная `overlay` (телефон). Переключает `watchSession()`
  по признаку screen-сессии. Ничего своего для телефона не строить.
- `setToggle(id, on)` и `setLabel(id, text)` обновляют обе панели; `setLabel`
  меняет видимую надпись кнопки (режимы показывают активное состояние).
- Статус-строка опыта (`setStatus`) обязана объяснять, что сейчас происходит:
  активный режим, источник данных, ошибки.

## Телефон (immersive-ar)

- Единственный работающий ввод — тап по экрану и удержание. Жесты рук и лучи
  на телефоне не существуют: не делать их единственным путём к функции.
- World-панель на телефоне вращается вместе с миром — по её кнопкам нельзя
  попасть. Экранный ввод только через `overlay` из `spatialControls`.
- Ретиклы на touch-устройствах отключены в `baseOptions` (белый круг-«тап»
  мешает). Не включать их обратно для телефонов.
- Контент привязывается якорем (`anchorRoot`) и стоит на месте; кнопки не
  должны «уезжать» при движении телефона.
- Никаких огромных белых вспышек/спрайтов на весь экран: эффекты тапа —
  компактные, цветные, ограниченные по времени и размеру (метры, не комната).
- Опыт обязан быть осмысленным без depth-sensing: если реальный меш недоступен,
  показывать честную деградацию (видимый фон/сообщение), а не чёрный экран.

## Режимы и данные

- Каждая кнопка режима меняет наблюдаемую композицию, а не один параметр
  вроде скорости вращения. Подпись кнопки отражает активный режим.
- «Живые» данные (погода, геолокация) — только после явного действия
  пользователя и успешного получения; до этого показывать явно помеченный
  демо-набор. Ошибка источника видна в статусе, не молчит.
- Погодный опыт проектируется от контекста: дата, время суток, сезон
  (полушарие по геолокации), полученные показатели. Разные условия дают
  различимые сцены (ясный день / дождь / снег / ночь), а не одну абстракцию.
- Хардкод-места (как CITY//ORBIT) не подаются как реальные геоданные.

## Проверка

- Каждый опыт открывается с `?test=1`: автостарт симулятора, состояние —
  в `document.documentElement.dataset.*` (`*State`, `*InitErr`, `*UpdateErr`).
- Мобильное поведение проверять эмуляцией телефона (touch + narrow viewport):
  кнопки overlay стоят на месте, тапы попадают, эффекты компактны.
- После правок общего shell прогнать все пять опытов: city-orbit,
  sound-space, weather-room, echo-room, reality-field.

## Скиллы и источники (читать перед правками)

- Официальные скиллы SDK лежат в `.agents/skills/xb-*` (синк из
  `node_modules/xrblocks/skills` канонического проекта `../xr-experiments`:
  `cp -r ../xr-experiments/node_modules/xrblocks/skills/* .agents/skills/`).
  Перед задачей читать профильный: `xb-add-spatial-ui` (карточки/оверлеи),
  `xb-add-interactions` (ввод/события), `xb-add-world-sensing` (depth/planes),
  `xb-anchors`, `xb-debug-app`, `xb-build-app`.
- Контракты SDK — `../xr-experiments/XR-BLOCKS.md`; полное зеркало апстрима —
  `../xrblocks-reference/` (templates/samples/demos/docs); символы сверять
  с `../xr-experiments/node_modules/xrblocks/src/`, мануал — Spatial UI
  (`UICard` — мир/метры, `UIOverlay` — view-space/приватный viewport,
  retained-обновления, `xb.ui.validate()`).
- Ветки docs по interactionMode: SDK его не использует; признак телефона —
  WebXR-спека (`interactionMode === 'screen-space'` + `targetRayMode`).

## Канон рендера (premultiplied-alpha)

- Рендерер XR Blocks — `alpha:true`, канвас premultiplied. Голый
  `THREE.AdditiveBlending` копит альфу и гасит камеру в alpha-blend-сессии.
  Каждый светящийся материал — через `glowBlending()` из `common/shaders.js`.

## Отклонения от канона (осознанные)

- `installXrGuards()` в `common/shell.js` (вызывает `baseOptions`): повтор
  `requestSession` без `depth-sensing/hand-tracking/local-floor` при отказе.
  SDK такого retry не делает — только `console.error`.
- Руки (`enableHands/enableGestures`) не включаем нигде, кроме reality-field
  на гарнитуре: ни один опыт не читает hand-данные, а флаг делает
  `hand-tracking` required-фичей и роняет вход на телефоне.
- `compose()` в reality-field — разовый камера-относительный док + пер-кадровый
  lerp якоря из shell, а не `FollowHead`/`FaceCamera`: нужен «док один раз»,
  placement-скрипты такого не дают.
- Звук — плоская лента 16 полос перед пользователем, а не 32 оси вокруг головы
  как в каноне: объёмная сцена — долг, тембровую классификацию не копируем
  (противоречит «форма = выбор визуализации»).
- `xb.ui.validate()` в проект не зовём: долг, проверять переполнение панелей.
- Симулятор не эмулирует телефонный alpha-blend и пустые planes: телефон и
  Quest — только реальное устройство (бюджета якорей это тоже касается).
