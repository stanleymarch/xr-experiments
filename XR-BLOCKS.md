## Структура: один опыт = один файл

Каждый опыт — `xrblocks/<name>/index.html` целиком: import-map CDN
(three@0.184.0, xrblocks@0.21.1, uikit-трио, lit), весь код в одном
`<script type="module">` с классом `xb.Script`, минимальные CSS-оверрайды
поверх официального `xr.css`. Рядом — `exp.json` (title/description/
description_ru/tags для галереи, читает `scripts/build-all.js`) и опциональные
`assets/`/`textures/`. Общего слоя `common/` нет: device-контракты (см. ниже)
инлайнятся в каждый файл дословно.

Скелет и контракты канонизированы пилотом `xrblocks/weather-room/index.html`:
при новом опыте — копировать его шапку и контракты, менять только тело опыта.

## Официальный путь (золотой промпт, коротко)

- Логика — только классы `xb.Script`/`xb.MeshScript`; `init()` — сетап,
  `update(delta)` — кадр, `dispose()` — освобождение. Своего
  `requestAnimationFrame` нет.
- UI — встроенный spatial UI: `xb.UICard` (мир, метры) для контента,
  `xb.UIOverlay` (view-space) для HUD/статуса/контролов. Числовые размеры
  детей — UIKit-единицы, `UICard.size` — метры, `height: 'auto'` — по контенту.
- Взаимодействие — через `object.xb` (manipulation, pointerEvents,
  reticleMode) и целевые колбэки (`onObjectSelectEnd(event)` и т.п.); свой
  `Raycaster` в колбэках ввода запрещён (видит другой кадр).
- Placement — скрипты-дети `xb.FollowHead` / `xb.FaceCamera` /
  `xb.FollowObject` и `xb.world.placeOnHorizontalSurface(...)`; для surface
  см. грабли ниже.
- Симулятор — дефолтные настройки; `options.xrButton.showEnterSimulatorButton
  = true`; автостарт `?formFactor=desktop`. Проверочные параметры:
  `?debug=1` (window.xb + xbReady), `?xrAutomation=1` (SDK-пресет; опыт
  обязан иметь детерминированную демо-ветку без сети/разрешений).

## Инлайненные device-контракты (5 штук, копировать дословно)

1. `glowBlending(material)` — premultiplied-alpha телефонного AR: обычный
   `AdditiveBlending` копит альфу канваса, композитор гасит камеру под
   «свечением». Раздельный blend: RGB аддитивно, альфа канваса не растёт.
   Все светящиеся материалы — только через него.
2. `installXrGuards()` — телефонный Chrome отклоняет сессию с required
   `depth-sensing/hand-tracking/local-floor`; повторный `requestSession`
   без непосильных фич.
3. `isPassthrough()` — `environmentBlendMode === 'alpha-blend'` = телефон
   (Quest отдаёт `additive`).
4. `hideInPassthrough(objects)` — VR-декорации комнаты (пол, дымка, купол)
   прячутся в AR.
5. `watchXrButton(hints)` — класс `.in-session` на `#XRButtonWrapper`
   (кнопка END XR → компактная пилюля) + подсказки в официальный entry-экран.

## Грабли SDK, найденные при переделке (2026-09)

- `world.placeOnHorizontalSurface` падает в `Box3.setFromObject` на
  uikit-мешах HUD (`RangeError`/дробный `Temporal.Duration`). Канон-обход:
  ретикловый `world.placeOnSurface` (см. `xrblocks/city-orbit`).
- GLSL ES строго к типам: `mod(i + 1, ...)` при `vec2 i` не компилится на
  ANGLE/Linux (`int + vec2`) — писать `i + 1.0`. Проехались дважды.

- `renderer.info.render.*` читается между кадрами как 1/1 (autoReset) —
  мерить рендер матрицами инстансов и весами анимаций, не только info.
- Текстура `snowflake1.png` из официального сэмпла rain — **непрозрачный квадрат**
  (проверено попиксельно): натягивать как спрайт нельзя, альфу строим вырезанием
  по яркости с авто-полярностью фона (см. загрузчик в `xrblocks/weather-room`).

## Принцип: реакция мира на данные

Каждое поле внешних данных обязано иметь **видимую причину в мире** — не
цифру в телеметрии, а изменение, которое видно глазом. Источник данных тоже
виден всегда: телеметрия каждого опыта начинается с префикса `LIVE · …` /
`DEMO · причина` / `AUTOMATION · …`, а не показывает его один кадр.

Эталон — WEATHER//ROOM: все десять полей ответа Open-Meteo ведут себя в
мире: `rain`+`showers` — число/скорость/крупность капель и мокрые пятна;
`snowfall` — снежинки и их накопление на полу; `cloud_cover` — плотность
плиты и объёмного облака; `visibility`/`weather_code` 45+ — мгла;
`wind_speed`+`wind_direction` — снос капель, наклон росчерка, дрейф плиты,
течение аэрозоля; `wind_gusts` — турбулентная дрожь аэрозоля;
`pressure_msl` — высота облачного потолка; `is_day` — палитра, звёзды,
уровень света (Hemisphere/Directional с вспышками молний); `temperature` —
цвет аэрозоля; `relative_humidity` — плотность пылинок. Новый опыт,
берущий данные из сети, проектируется от этого же правила.

## Как проверять, не гадая

1. **Синтаксис**: `awk '/<script type="module">/{flag=1;next}/<\/script>/{flag=0}flag'
   xrblocks/<name>/index.html > /tmp/m.mjs && node --check /tmp/m.mjs`.
2. **Flat-режим** (просто браузер): открыть без параметров — сцена рендерится,
   HUD живой, мышь работает.
3. **Симулятор**: `?formFactor=desktop` — автостарт, ретикл, USER/POSE-режимы.
4. **Automation**: `?xrAutomation=1&debug=1` — детерминированная ветка,
   `window.xb` для проб, консоль должна быть чистой.
5. **Планка качества** — официальные сэмплы <https://xrblocks.github.io/docs/samples/>:
   в том же браузере они чистые — наши должны быть тоже.
