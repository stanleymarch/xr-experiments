# LANTERN // VOID — генеративная экология вычислительных тел

## Что это

Практическая работа № 1 семинара «Проектирование (не)человеческих систем» —
«Символическая машина» (концепция: `docs/ideas/lantern-void.md`). Основа — авторская
версия **v6.3** (три файла в духе OpenProcessing/p5 Web Editor). Эпиграф: «Она
кричит о своем существовании» — каждый импульс тел — крик без адресата.

Грамматика мира — **v1** (26.11): восемь операторов, у каждого собственный механизм
(SOURCE, SENSE, FILTER, DELAY, MEMORY, FEEDBACK, GATE, EMIT); граф каждого тела
выращивается по seed (102 возможных графа); форма и имя — чтение графа. Внешний вид,
структура файлов и интерфейс шлема — авторские; правила переписаны по результатам
измерений. Три вещи, которых в v6.3 не было: **«мир без вас»** — двойник мира, в который
присутствие не входит (счётчик «сигналов · без вас»); строка **«как это читается»** —
правило перевода событий на человеческий язык, которое можно выключить; живые
показания операторов в инспекторе.

Для сдачи нужны три вещи: работающий прототип, описание его правил и комментарий
о роли генеративной модели. Вторая и третья — в **[`docs/lantern-void-rules.md`](lantern-void-rules.md)**:
правила мира по разделам кода и сравнение «предсказано моделью → измерено». Какой
оператор что меняет в поведении мира, проверяется прогоном `test/rules-ab.mjs`.

Стек: **p5.js 2.4.0** (мир + 2D-генеративка + звук) + **A-Frame 1.8.0 / THREE r184**
(опциональный пространственный мир VR/AR). Без сборки: CDN + ES-скрипт как есть.
Живёт в `apps/lantern-void/` — все опыты репозитория теперь в одной папке `apps/`;
сборщик публикует статические папки как есть (раздел каталога задаёт `"stack"`
в `exp.json`), адрес на Pages — `p5/lantern-void/`.

## Режимы и роутинг

Определение возможностей — только через `navigator.xr` + Permissions Policy
(user-agent сниффинг удалён; кнопки по `false`-пробе больше не прячутся, отказ
честный — в момент входа `openXR` переспрашивает поддержку заново):

| Экран | Условие | Что происходит |
|---|---|---|
| Пролог (вводный) | всегда | мир уже живёт за ним; 4 входа: «Войти», «Как устроено», «VR-мир», «AR в комнате» |
| Живой вид (flat) | по умолчанию | p5-сцена: наблюдение / возмущение, инспектор тел с живыми показаниями операторов, «как это читается», счётчик «сигналов · без вас», пауза, звук, пересев (клавиши R/P/Space) |
| VR-мир | `immersive-vr` ✓ | A-Frame-сцена: тела с шейдерными оболочками, луч+триггер, контекстное меню (Y), ходьба стиком, снап-поворот 30°, руки (pinch), пространственный звук |
| AR в комнате | `immersive-ar` ✓ | hit-test размещение миниатюры (scale 0.125), физическое перемещение, «приближение меняет поле» |

Мобильные/узкие вьюпорты: адаптивный компакт-пролог — меню входа не уезжает за
нижний край при видимой паре VR/AR (v6.3.1 fix). Кнопки входа унифицированы:
текст по центру, одинаковые вес/трекинг/кегль символов в RU и EN (v6.3.2 fix).

## Структура

- `index.html` — пролог, живой UI (журнал, «как это читается», счётчик двойника),
  инспектор, модалка правил (основания и правила v1); XR-сцена собирается программно
  при первом входе.
- `mySketch.js` — весь опыт: правила и грамматика, мир и его двойник (фиксированный
  шаг 1/60, seeded), плоский вид, интерфейс, звук и пространство A-Frame. Разбит на
  разделы 01–09 с оглавлением в шапке, у каждой функции — пояснение. Отладочный API
  `window.lanternDebug` (полный список — комментарий в разделе 03): заглянуть в мир
  (`getState`, `structure`, `names`, `reading`, `spatialLayout`, `audioStats`, `xrState`,
  `xrMenuAudit`, `shadow`, `compare` — мир против «мира без вас», `rules`), прокрутить
  его (`simulate`, `trace` — события по шагам), вмешаться (`reset`, `injectPresence`,
  `agitate`, `fieldGain`, `stimulate`, `tune`, `setRules`, `ablate` — убрать оператор
  у всех тел, кроме заданного).
- `style.css` — оформление экранной части; последний блок — «как это читается»,
  показания операторов, счётчик двойника.
- `test/e2e.mjs` — headless-прогон всех режимов (Playwright из apps/weather-room), включая
  проверки наличия: нечисловых аргументов рисования нет, показания операторов, «как это
  читается», счётчик двойника на обоих языках; `LANTERN_BASE=http://localhost:8096/p5/lantern-void`
  прогоняет его же против собранного `_site` — проверка опубликованного артефакта.
- `test/rules-ab.mjs` — «предложено → измерено» для грамматики v1 (58 проверок): контроль
  инструментов, грамматика, живость (40 миров), развёртка слушателя (одинаковый сигнал),
  зависимость от партнёров, каждый оператор на изолированном теле, присутствие и двойник,
  seed (102 графа; громкость мира — его население), чтение и имена. Числа для
  `docs/lantern-void-rules.md`.
- `test/world-rules.mjs` — seed → структура мира (8 миров, графы и формы), одно поле p5
  для симуляции, плоского вида и шейдеров, захват тела курсором и grip'ом.
- `test/xr-scenarios.mjs` — сценарии VR на имитации настоящей сессии (меню, ходьба,
  поворот, выбор, система без пола) и отсутствие нечисловых значений в телах.
- `test/first-entry.mjs` — первые секунды в шлеме: нулевая поза входа, меню по
  настоящей голове, плоскость поля не гасит тела, вход именно в AR или в VR.
- `test/canvas-dump.mjs` — выгрузка всех canvas-текстур XR (меню, панели) в PNG
  в `test/tmp/canvas-dump/` + проверка «аспект канваса = аспекту плейна» для каждой.
- `test/xr-acceptance.mjs` — приёмка в пространстве по чек-листу Meta
  (`hz-immersive-designer`): прозрачные материалы сцены по семействам, меню поверх мира
  (порядок отрисовки и цвет плашек на готовом кадре), размер кнопок и высота букв по
  пикселям текстур, скорость ходьбы, подход к телу ходьбой и рука у тела (крики против
  «мира без вас»), наведение и триггер, рука и grip. Тоже на имитации настоящей сессии.
- `test/iwer-run.mjs` + `test/iwer/xr-session.mjs` — оркестратор эмулятора: стейджит
  опыт в apps/weather-room/lantern-test, поднимает рантайм IWSDK с Meta XR Simulator,
  входит в настоящую XR-сессию эмулятора и проверяет: тик не падает, мир идёт в сессии,
  меню в зоне, ходьба, поворот, триггер по телу — и убирает за собой. Ввод подаётся
  событиями на страницу: эмулятор не передаёт ввод устройств на не-IWSDK-страницу.
- `en-US.json` — пустой словарь локали (p5 2.x иначе 404ит от корня страницы).

## Интерфейс в шлеме: правила Meta (`hz-immersive-designer`)

- **Меню** — панель 1.4 м от глаз (для рук 1.0 м), центр на 12° ниже уровня глаз,
  целиком в первичной зоне взгляда, без крена, перпендикулярна линии взгляда.
  Измерено (`test/xr-acceptance.mjs`): панель 0.84×0.66 м (33° по ширине), не ближе
  0.87 м; кнопки 75×112 мм с зазором 12 мм; высота букв 1.49–1.98° (минимум по
  чек-листу — 1°). Стоит в мире, не следует за головой. Четыре кнопки: «Моё влияние»,
  «Звук», «Как управлять», «Вернуться в 2D»; в шапке подсказка «B: закрыть». На
  странице «Управление» подсказки — текст, нажимается только «← К настройкам».
- **Меню рисуется поверх мира.** Тело у руки стоит в 1.26 м, меню открывается в 1.4 м,
  и ядро со свечением тела оказывались перед кнопками. Фон, плашки и подписи не
  проверяют глубину и идут с порядком 55–60 (объекты мира — 0, карточки — 22), ниже
  прицела на конце луча (74–75). На готовом кадре плашки — ровно заданного цвета.
- **Движение — ходьба левым стиком и снап-повороты правым (30° за шаг), вокруг
  головы.** Телепорта нет: в космосе нет пола, а случайное переключение на него
  лишало ходьбы. Виньетки нет — нет «дороги», укачивать нечему (решение автора
  опыта; от правила Meta «виньетка при плавном движении» отступлено сознательно).
- Открытое меню не запирает движение.
- Подсказка «триггер — сведения» не налезает на карточку выбранного тела.
- Hover кнопок — подсветка и точка-прицел; выбор подтверждается звуком
  (`playUiBlip`: у рук нет вибрации контроллера) и вибрацией, если она доступна.
- Цвет луча меняется только при смене hover (раньше — каждый кадр).
- Текст в шлеме рисуется на canvas (Canvas2D), не `<a-text>`: в его шрифтовом
  атласе нет многих глифов, и русский текст превращается в точки.

## Что проверено и что нет

**Четыре слоя проверки** (скрипты в `apps/lantern-void/test/`):
1. `e2e.mjs` — плоский режим в headless-браузере.
2. `xr-scenarios.mjs`, `first-entry.mjs` — VR на **имитации настоящей сессии**:
   вызывается настоящий `look-controls.onEnterVR()` A-Frame (сущность камеры
   обнуляется, как с гарнитурой), поза гарнитуры задаётся THREE-камере. Скриншоты
   «как в шлеме» → `test/tmp/xr-shots/`.
3. `xr-acceptance.mjs` — приёмка по чек-листу Meta на той же имитации: прозрачные
   материалы, меню, движение, подход к телу, триггеры, руки.
4. `iwer-run.mjs` — живая сессия Meta XR Simulator (через рантайм IWSDK).

Правила мира — по числам симуляции, без шлема: `world-rules.mjs` (структура, поле,
захват) и `rules-ab.mjs` (что каждый оператор меняет в поведении мира).

Статический контроль: `tsc --checkJs` на неопределённые имена (ловит ссылки на
удалённый код).

**Почему первые отчёты с устройства не ловились (урок 2026-11-24).** Эмулятор не
давал настоящей XR-сессии, а тесты не имитировали то, что A-Frame делает в
настоящей. Плюс ошибки в самих тестах: «ошибок тика нет» читалось через
несуществующую функцию (`n/a` засчитывался как успех), а остановку времени мира в
сессии ошибочно списали на эмулятор.

**Причины симптомов с устройства (v6.3.4):**
1. *Меню под ногами.* A-Frame при входе в сессию с гарнитурой обнуляет
   **сущность** `#xr-camera` (`look-controls.onEnterVR`: `position.set(0,0,0)`,
   `matrixAutoUpdate=false`), а позу гарнитуры применяет к внутренней
   THREE-камере. Код брал «голову» у сущности → в шлеме она в нуле → меню,
   карточки тел, поле присутствия и слушатель звука уезжали на 1.65 м вниз.
   Исправление: единый источник головы `xrHeadPosition()/xrHeadForward()`
   (THREE-камера) во всех десяти местах.
2. *Не могу ходить, тела не двигаются.* Тик падал каждый кадр на «ребейзе
   высоты» (`rig.position` у HTML-элемента вместо `rig.object3D.position`), а
   `try/catch` молча глотал ошибку — всё, что шло в тике после неё, не
   выполнялось: опрос стиков, ходьба, симуляция, анимация. Падение случалось
   только при настоящем `vr-mode`. Исправлено; подъём рига теперь по реальной
   высоте головы и только когда она < 0.8 м (система без пола).
3. *Меню запирало ходьбу.* Подсказка при входе открывается сама, а открытое
   меню блокировало стики. Теперь меню не запирает движение.

**Проверено (26–27 ноября 2026; семь наборов по финальному коду против исходников;
`e2e`, `rules-ab`, `xr-scenarios`, `xr-acceptance` — ещё раз против артефакта
`p5/lantern-void/`, собранного настоящим `npm run build`; файлы артефакта совпадают с
исходниками байт в байт):**
- **Плоский режим** (`e2e`, 42/42; по артефакту 42/42): пролог, языки, вход, журнал,
  инспектор с живыми показаниями операторов, «как это читается» (скрыто → показано →
  скрыто; на английском без кириллицы), счётчик «сигналов · без вас» с числами из мира.
  Курсор в «Возмущать» разводит счётчики мира и «мира без вас» — через 0.83 с мира по
  исходникам и 0.77 с по артефакту (бюджет проверки — 5 с), и счётчик это показывает
  (40 · 39). Вызовов рисования с нечисловыми аргументами нет; детектор проверен на
  заведомо плохом вызове.
- **Имитация настоящей сессии** (`xr-scenarios`, 27/27; по артефакту 27/27): меню
  1.4 м / 12° вниз / y = 1.41 (не под ногами); риг не задран; сим-время растёт; ошибок
  тика нет (по настоящему списку `xrState().tickErrors()`); ходьба при открытом меню;
  B/Y; четыре кнопки, телепорта в меню нет; клики по кнопкам лучом и триггером;
  снап-поворот 30° без сдвига головы и ходьба после него; выбор тела с карточкой у тела;
  система без пола — риг поднят; в телах нет нечисловых значений (152 объекта в 10 телах).
- **Первый вход** (`first-entry`, 14/14): окно нулевой позы после входа в сессию, меню
  не раньше 90 кадров после `enter-vr` и по настоящей голове, плоскость поля без
  заливки, «AR в комнате» входит в AR, «VR-мир» — в VR.
- **Приёмка по чек-листу Meta** (`xr-acceptance`, 31/31; по артефакту 31/31), числа из
  прогона по исходникам:
  - *прозрачные материалы*: каждый видимый прозрачный объект принадлежит задуманному
    семейству (тела, связи, поле среды, звёзды, карточки тел, меню, прицелы); крупной
    полупрозрачной плоскости поверх тел нет; плоскость поля рисуется раньше тел
    (`renderOrder = −1`); единственный объект вне семейств — служебная невидимая
    плоскость A-Frame (`bboxMesh` компонента `ar-hit-test`), опознанная по ссылке;
  - *меню*: 1.4 м от глаз, ближайшая точка 0.87 м, ширина 33.4°, кнопки не меньше
    48 мм с зазором 12 мм, высота букв 1.49–1.98°; рисуется после мира (порядок 55–60
    против 0) без проверки глубины; на готовом кадре плашки ровно заданного цвета —
    самый яркий канал 83 из 255;
  - *движение*: ходьба 1.15 м/с, только вперёд по взгляду; снап-поворот 30°;
  - *подойти к телу*: «Порог» — 2.15 м → 1.06 м, влияние 0.10 → 0.21; рука в 0.3 м от
    ядра 6 с мира — 16 криков против 6 в «мире без вас»; после отхода на 2.9 м — 0.05;
  - *триггер*: наведение подсвечивает ровно одну кнопку, нажатие выполняет её действие;
  - *руки*: свободная рука — источник 0.9 с радиусом 1.05 м; grip у тела захватывает
    его (зазор 0.85 → 0.02 м); в свободном пространстве с grip — 1.25; у самого тела —
    1.65 с радиусом 0.72 м, касание зарегистрировано.
- **Правила мира**: `world-rules` 63/63 — 8 seed → 8 разных структур, детерминизм,
  одно поле p5 для симуляции, плоского вида и шейдеров, захват курсором (сдвиг 0.93 м,
  возврат домой) и grip'ом (сдвиг 0.83 м, встряска 0.82, возврат домой за 16 тиков;

  58/58) — что каждый оператор меняет в поведении мира; числа для
  `docs/lantern-void-rules.md`.
- Canvas-текстуры меню и панелей выгружены в PNG и просмотрены: кириллица без
  обрезки, аспект каждой текстуры совпадает с аспектом её плоскости (25/25).
- Статический контроль: `tsc --checkJs` (TypeScript 5.9.3, только «Cannot find name») —
  в `mySketch.js` и девяти файлах тестов неопределённых имён нет.
- **Живая сессия эмулятора** (`iwer-run`, 10/10; 26.11, рантайм IWSDK зарегистрировался
  со второй попытки): настоящая XR-сессия Meta XR Simulator — сессия вошла (10 тел),
  гид-меню в 1.4 м и на 12° ниже глаз без крена, время мира растёт (1.87 → 5.85 с),
  ходьба при открытом меню (0 → −2.75 м), B закрывает меню, снап-поворот 30°, триггер
  выбирает тело, ошибок тика нет.

**Границы эмулятора (доказано):**
- IWER не пробрасывает ввод эмулятора на не-IWSDK страницы (`xr enter` требует
  `world.xr.offer` из IWSDK-приложения) — контроллеры подаются событиями, в штатные
  обработчики опыта.
- Скрипт сессии сам ставит счётчик кадров (`ticks = 200`), поэтому первые секунды после
  входа и нулевую позу он не проверяет — это делает `first-entry` на имитации.
- Meta XR Simulator сам веб-страницы не открывает (Unity, Unreal, нативный OpenXR) —
  сессия идёт через рантайм IWSDK.
- A-Frame кэширует `immersive-ar=false` из ранней пробы эмулятора → `enterAR()`
  отказывает. **AR-размещение в эмуляторе непроверяемо.**
- Стерео-рендер, трекинг реальной гарнитуры, настоящий геймпад и вибрация — только на
  устройстве.

**За устройством (Quest 3):** подтвердить в шлеме: меню перед глазами и читаемое в
линзах (буквы 1.49–1.98°), меню поверх мира, ходьба стиком и живой мир, комфорт ходьбы
без виньетки (решение автора), настоящие контроллеры — наведение, триггер, B/Y, grip и
захват тела, AR-размещение миниатюры (ретикл 0.14 м, один триггер ставит мир).

**Не проверено нигде:** как опыт читает живой зритель — тест восприятия (§11 концепции)
требует людей.

## Тройка для OpenProcessing

Опыт целиком — три файла в `apps/lantern-void/`: `index.html`, `mySketch.js`,
`style.css`. Внутри нет ни импортов, ни сборки, только библиотеки с CDN; файлы
взаимозаменяемы с вкладками OpenProcessing один к одному. `mySketch.js` разбит на
пронумерованные разделы (01 Правила … 09 Запуск) с оглавлением в шапке; у каждой
функции — комментарий, что она делает и от чего зависит. `index.html` и
`style.css` размечены по разделам.

При чистке (2026-11-24) удалено: телепорт (пять функций, состояние, невидимый
пол, обработчики кнопок), HUD-панель, которая ни разу не показывалась, подсказки
AR, которые никогда не выводились, стартовая проверка поддержки XR, на которую
ничто не смотрело, 13 полей состояния без читателей, 2 параметра `RULES`,
3 поля мира, 2 цвета палитры, функция `smooth`, ручка `noiseSeed` (шум p5 в
опыте не используется), 6 строк словаря RU и EN без ссылок, обёртки-дубли.
